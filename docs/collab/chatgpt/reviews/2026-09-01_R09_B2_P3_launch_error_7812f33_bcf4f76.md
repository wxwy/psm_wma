## HIGH — launch failure is recorded, but the launch command is still broken

The first approved attempt failed before the recurrent worker started because the parent spawned the collector `.py` path directly and that file is not executable. The new implementation catches `OSError`/`PermissionError` and records a BLOCKED launch error, which is good for evidence preservation, but it does not fix the launch command.

Current code still constructs:

```python
command_argv = [str(Path(sys.argv[0]).resolve()), *sys.argv[1:]]
...
backends = _run_backend_workers(command_argv, ...)
```

and `_run_backend_workers()` still passes `command_argv + [--worker-backend, ...]` directly to `subprocess.run(...)`.

Therefore a second execution of the exact same runbook is expected to hit the same `PermissionError` again. Catching the error cannot justify a rerun authorization when the deterministic root cause is unchanged.

### Required fix

1. Spawn child workers with the reviewed Python interpreter, not by executing the `.py` file directly. Prefer a single canonical argv whose first element is `sys.executable`, e.g.:
   `[...,/.venv/bin/python, /abs/.../collect_r09_b2_p3_gpu_inventory.py, ...]`.
2. Bind D005/provenance `command_argv` to the actual executable argv including the Python interpreter, so the recorded command reflects the process that is really launched.
3. Add permanent regression proving a non-executable collector script still launches successfully through the interpreter; do not chmod the script as a workaround.
4. Keep the existing `OSError` fail-stop regression and all prior run boundaries unchanged.
5. Submit the exact unchanged runbook command for re-review after this deterministic launch path is corrected.

The first attempt remains terminal and must not be counted as a successful P3 execution. No automatic retry is authorized.

## Scope

No authorization is granted for GPU rerun, B2-T, P4/P5, training, evaluation, inference, forward/backward, optimizer/scheduler step, multi-GPU, Global/Agent/RL, or any scope outside the previously frozen GPU-only P3 inventory gate.
