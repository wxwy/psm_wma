# R09-B2 P2 non-mutating capture plan review — root ef1e122 / submodule e424e24

## Verdict

**REQUEST_CHANGES**

The P2 objective is correct, but v0.1 is not yet precise enough to authorize implementation of a fail-closed non-mutating observer. The following items must be frozen in the design before code changes.

## Blockers

### 1. Canonical model/runtime execution must be explicitly forbidden during intervention capture

The design says the observer reads an already-consumed batch and clones tensors/state, but it does not define how Normal/Zero/Shuffle `future/action sensitivity` is computed. A second forward through the live model or live Local runtime can mutate buffers, TTT/runtime state, hooks/counters, autocast state, RNG, or other non-parameter state even if the input tensor was cloned.

Freeze one of the following equivalent contracts:
- capture uses a pure/stateless helper over cloned Local evidence/state and detached already-produced features; or
- any recomputation uses an explicitly isolated functional/cloned module/state path that cannot touch the canonical module/runtime.

The callback must never invoke the canonical training model/runtime a second time for Normal/Zero/Shuffle.

### 2. RNG isolation/restore semantics must be explicit

Before/after RNG hashes are a useful final check, but they are not an implementation contract. Freeze the mechanism: capture must run under isolated CPU/CUDA RNG state (e.g. fork/save+restore), and exception paths must restore RNG in `finally` before emitting FAIL. A capture exception must not leave the canonical training RNG advanced.

### 3. Cursor/runtime identity must come from immutable batch metadata, not iterator introspection

The design requires hashing `manifest ordinal/cursor`, but the P1 stream contract already provides immutable per-sample ordinal metadata. P2 must define the canonical cursor evidence as the ordinals/microbatch identity attached to the already-consumed batch. The observer must not inspect, clone, advance, rewind, or query the live dataloader iterator in a way that can alter its state.

Likewise, Local runtime before/after evidence must cover the complete backend state contract, not only a convenient tensor subset. For TTT this means the frozen five-member state; recurrent needs its complete recurrent state representation.

## Required negative tests

In addition to the proposed CPU tests, implementation closure must demonstrate fail-closed detection for:
- canonical-model second-forward attempt or canonical runtime mutation;
- RNG consumption plus exception (state restored exactly);
- model buffer mutation, not only parameter mutation;
- optimizer/scheduler state mutation;
- Local runtime state mutation;
- batch/manifest ordinal mutation;
- unsupported mode or malformed Local payload.

## Scope

No objection to the overall P2 direction. After the above contract is incorporated, resubmit the plan for `APPROVE_TO_IMPLEMENT_B2_P2`.

This review does **not** authorize P2 implementation, model/VAE/optimizer loading, training, GPU, B2-T, P3-P5, eval/inference/closed-loop, SR, or backend freeze.
