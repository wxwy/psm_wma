## Non-blocking robustness notes

### LOW-1 — `history_dt_s` does not have an explicit finite check

Visual/action/state inputs are explicitly finite-checked, while `history_dt_s` is only shape-checked before `dt_proj`.

Current Step 3 guarantees the actual dataset dt comes from validated timestamp differences and the Step 4 artifact is finite, so this is not a blocker.

Before official runtime wiring, it would be cleaner to reject non-finite dt explicitly.

### LOW-2 — negative `state_std` is floored rather than rejected

`state_std.clamp_min(state_std_floor)` safely handles zero/tiny std, but a negative std is logically invalid and more likely indicates a corrupted stats artifact.

When the real train-split stats pipeline is added, prefer:
- reject negative std;
- floor only zero/tiny non-negative values.

This does not affect the current runtime because state remains disabled pending real train-split stats.
