## Additional findings

### HIGH — generic hidden child request still bypasses the parent gate

`tools/g0/export_r09_b2_p5_resolved_config.py` child/main path

The child bootstrap is now self-contained and can run under the frozen D005 cwd/environment. However, `main()` still accepts `--child-request/--child-output` directly, and `_child()` trusts TOML, overrides and backend from that request after checking only that the current cwd/interpreter/environment match values carried in the same caller-authored request.

The v0.4 design states that the child consumes a parent-generated/authenticated D005-bound request. That property is not implemented. A caller can construct an internally consistent request under the exact D005 cwd/interpreter/environment and bypass production/evidence/exporter root validation and the parent pair gate before invoking `load_experiment_from_toml`.

Required:
- make the standalone child independently reject requests that are not one of the verifier-owned D005-bound request identities; a self-declared hash inside the same request is insufficient;
- validate an exact child request schema and immutable verifier-owned D005/request digest(s) before production compose;
- add a CPU negative showing an arbitrary but internally consistent request under exact D005 cwd/interpreter/env is rejected at pre-compose guard.

### MEDIUM — failed staging attempts are preserved but not marked FAIL

`run_parent_export()` creates a UUID attempt directory and promotes it only after verifier PASS, which correctly protects the canonical output path. But exceptions from a child or verifier leave the attempt directory without the v0.4-required canonical FAIL marker/status record.

Required: catch the parent-boundary failure, write a deterministic failure record inside the attempt directory, keep canonical result absent, then re-raise.
