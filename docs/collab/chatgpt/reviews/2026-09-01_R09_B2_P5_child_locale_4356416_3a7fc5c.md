## Scope

This review is limited to the static remediation after the previously authorized one-shot P5 export failed closed at the child environment guard. It does not authorize another export attempt, compose, GPU work, training, P5 closure, or B2-T.

## Findings

### HIGH — exporter effective environment and pair-verifier contract are now inconsistent

`tools/g0/export_r09_b2_p5_resolved_config.py:112-132` changes `sanitized_environment()` so every child effective environment contains the frozen runtime locale `LC_CTYPE=C.UTF-8` unless the D005 contract explicitly unsets it, in which case the exporter fails closed. This is a narrow and reasonable fix for the reported Python startup locale coercion.

However, the P5 pair verifier was not changed. In `tools/g0/verify_r09_b2_p5_full_config_diff.py` inside `_bound()`, the verifier still requires:

`environment["effective"] == record["environment"]["set"]`

The frozen P4 record does not contain `LC_CTYPE` in `environment.set`. Therefore an envelope assembled by the remediated exporter will contain:

`effective = record.environment.set + {"LC_CTYPE": "C.UTF-8"}`

while the verifier still requires exactly `record.environment.set`. If both children successfully compose, `recurrent_bound` and `ttt_bound` will be false and the pair verifier will return FAIL. The remediation therefore fixes the pre-compose child guard but makes a successful P5 static export impossible to pass the final verifier.

Required fix:

1. update the verifier-owned expected effective environment to include exactly the frozen startup locale and no other additions; do not weaken this to subset/superset matching;
2. keep `environment.set`, `unset`, and `inherit_allowlist` bound exactly to the frozen P4 record;
3. add a negative proving any additional or changed effective-environment key still FAILs;
4. update the permanent positive fixture to construct the same effective environment that the real exporter now produces, and require `verify_pair(...)["status"] == "PASS"` for that exact shape.

### MEDIUM — current 7/7 fixture masks the verifier/exporter mismatch

`tools/g0/test_r09_b2_p5_full_config_diff.py` `_pair()` still builds the synthetic envelope with:

`"effective": record["environment"]["set"]`

rather than using the remediated effective environment containing `LC_CTYPE=C.UTF-8`. Thus the existing verifier positive test continues to PASS only because it models the old envelope shape, not the shape `assemble_envelope()` will now emit from a real remediated child request.

Required fix: derive the fixture effective environment from the same frozen runtime contract expected by the verifier, then retain exact-schema and extra-key negative coverage.

## Positive observations

- The remediation remains narrow: exporter + P5 test only; no Cosmos submodule change.
- `PYTHON_CHILD_LOCALE={"LC_CTYPE":"C.UTF-8"}` is explicit rather than caller supplied.
- `sanitized_environment()` rejects a D005 contract that asks to unset the required child locale instead of silently overriding that contract.

- The request explicitly does not ask to rerun the export before static review.
