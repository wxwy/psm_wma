## Executive summary

The minimal recurrent backend is a reasonable A0 implementation direction:

- `GRUCell` is isolated from the production Cosmos runtime;
- masked timesteps use `torch.where(valid, proposed, state_in)`;
- `reset_mask` is per-sample;
- segment carry with detached state is implemented;
- no GPU/A1/TTT work is present.

However, the submitted `PASS` artifact does **not** prove the frozen A0 contract.

There are four blocking evidence/contract problems:

1. artifact provenance is stale and does not describe the submitted implementation;
2. verifier `status=PASS` depends almost only on one state-diff check, while several required assertions are hard-coded or not included in PASS;
3. required meta -> to_empty -> explicit-init lifecycle and deterministic init were not executed;
4. the partial-reset and segment/token tests are incomplete/vacuous in ways that can PASS without proving the intended behavior.

These are CPU-only closure items. No redesign or GPU rerun is needed.

## HIGH-2 — verifier PASS logic is not strict; several required assertions are hard-coded

`tools/g0/verify_r09_a0_contract.py` currently computes:

```python
status = "PASS" if diff <= 1e-6 else "FAIL"
```

where `diff` is only:

```python
(second - state).abs().max()
```

Therefore the final artifact can still say PASS even if:

- all-mask presence is wrong;
- partial reset is wrong;
- masked timestep changes state;
- init is non-finite/nondeterministic;
- provenance is invalid;
- batch permutation isolation fails;
- token segment equivalence fails.

Worse, the artifact currently writes:

```python
"masked_timestep_inert": True
```

without running a recurrent-backend masked-timestep perturbation check.

And:

```python
"token_max_abs_diff": diff
```

reuses the **state** diff instead of measuring token diff.

### Required fix

Build an explicit `hard_pass` from every frozen A0 hard assertion.

At minimum PASS must require:

- valid provenance;
- finite params/state/tokens;
- fixed-seed init determinism;
- mixed presence exact;
- all-mask `present=false`;
- masked timestep state inertness from an actual perturbation/check;
- batch permutation isolation;
- selected-sample partial reset;
- non-reset samples unchanged;
- segment state diff <= 1e-6;
- actual segment token diff <= 1e-6;
- detach carried-value exact;
- required schema fields present.

Do not hard-code assertion booleans.

## HIGH-3 — frozen production initialization lifecycle was not tested

The approved runbook explicitly requires:

```text
meta
-> to_empty
-> explicit fixed-seed init
-> all parameters finite
-> same seed gives elementwise-identical parameters
```

or an explicitly audited post-materialization-attach path.

Current verifier only does:

```python
torch.manual_seed(4)
backend = RecurrentLocalMemoryBackend(...)
```

The artifact says:

```text
init.path = "CPU contract constructor"
```

That is neither a meta->to_empty test nor an audited post-materialization attachment proof.

This is exactly the class of initialization bug R08 previously exposed.

### Required fix

For the A0 backend, add an explicit initialization entry point suitable after `to_empty` (for example a narrow `reset_parameters()` delegating to the recurrent cell), then CPU-test:

```text
with torch.device("meta"):
    backend = ...

backend.to_empty(device="cpu")
backend.reset_parameters()
```

Run twice under the same seed and assert every trainable parameter:

- finite;
- elementwise identical.

Record the result, init seed/path, parameter count and parameter prefixes in the artifact.

If the intended architecture is instead to attach R09 only after materialization, freeze that as the implementation contract and test that exact path. The current submission does neither.

## HIGH-4 — partial-reset and segment evidence do not prove the intended assertions

### A. Partial reset is vacuous

The test/verifier creates:

```text
sample 0: valid
sample 1: all-mask
sample 2: valid
```

Then resets:

```python
done = [False, True, False]
```

But sample 1 already has zero state because it was all-mask from zero initialization.

So this assertion:

```python
count_nonzero(reset[1]) == 0
```

does **not** prove that `reset_mask` can clear a nonzero recurrent state.

### Required partial-reset test

Use at least two samples with demonstrably nonzero pre-reset states.

For example:

```text
before:
sample 0 != 0
sample 1 != 0
sample 2 != 0

done = [False, True, False]

after:
sample 1 == exact zero
sample 0 == before sample 0
sample 2 == before sample 2
```

Record both selected-reset-zero and untouched-exact booleans.

### B. Token segment equivalence is not measured

The test compares only:

```python
second_state vs full_state
```

It does not compare the actual token returned by the full replay against the token returned by segment 2.

The verifier then reports token diff by copying the state diff.

Required:

- retain `full_tokens`;
- retain `segment2_tokens`;
- compare them directly;
- record the real token max_abs_diff.

### C. detach carried-value exact is not tested

The runbook froze:

```text
carried value detach 前后 exact
```

Current code calls `first.detach()` but never asserts:

```python
torch.equal(first.detach(), first)
```

Record this explicitly.

## MEDIUM — batch permutation isolation and recurrent masked-step inertness are missing

The frozen A0 contract also requires batch isolation.

Current new test has no permutation test for `RecurrentLocalMemoryBackend`.

Add:

```text
baseline = replay(batch)
permuted = replay(batch[perm])
unpermute(permuted) == baseline
```

for state, token and `present`.

For masked-step inertness, perturb the evidence at a masked timestep by a large finite value and prove final state/token are unchanged. Do not rely on the existing R08 `LocalEvidenceEncoder` masked-input test; A0 must prove the recurrent state update itself is mask-inert.

## True-absence note

The current backend returns a dense zero token plus `present=false` for an all-mask sample.

For A0 module-contract purposes this representation is acceptable **only if `present=false` is the authoritative absence signal** and later runtime packing is required to omit that token.

Do not claim A0 has already proven production `not-packed`; production packing remains an A1/runtime integration invariant.

The A0 artifact should phrase this as:

```text
all_mask_present_false = true
```

rather than treating zero-token equality alone as proof of not-packed absence.
