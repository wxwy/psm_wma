## Findings

### HIGH — interpreter exception leaks into the generic runtime/output allowlist

`tools/g0/verify_r09_b2_p4_d005.py` now adds the resolved canonical interpreter parent to both `_asset_ok()`'s generic `allowed` tuple and `_allowed_roots()`. `_allowed_roots()` is also used by `_env_ok()` and `_output_ok()` to authorize `IMAGINAIRE_OUTPUT_ROOT` / derived run roots. Therefore a D005 can now place its future output tree under the uv-Python interpreter directory and still pass. The same generic `_asset_ok()` also allows non-interpreter assets (base checkpoint, Edge processor, VAE, LIBERO/cache roots) to live under that interpreter directory.

That is broader than the requested fix. The interpreter symlink/realpath needs a narrow exception; it must not enlarge the verifier-owned roots for model/data/output assets.

Required change:

1. Keep runtime/output roots on the original verifier-owned allowlist; do not add the interpreter parent to `_allowed_roots()` used by `IMAGINAIRE_OUTPUT_ROOT` / `_output_ok()`.
2. Special-case only the `external_assets.interpreter` entry, or verify it directly against the exact canonical `(root / "cosmos-framework/.venv/bin/python").resolve()` realpath + SHA.
3. Keep all other external assets on their existing root-specific allowlist.
4. Add permanent negative regressions showing that an output root or a non-interpreter asset under the interpreter parent fails.

### MEDIUM — `external_assets.interpreter` is no longer bound to `command.interpreter`

After the PYTHONPATH fix, `_env_assets_bound()` no longer reads `assets["interpreter"]`. `_argv_ok()` correctly binds `command.interpreter` to the canonical `.venv/bin/python` realpath and SHA, but the `inputs.external_assets.interpreter` record can now point at another existing hashed file inside any allowed root and still pass `_inputs_ok()`.

Required change:

- Require `inputs.external_assets.interpreter.realpath` and SHA256 to exactly match `command.interpreter.realpath` and SHA256 (and preferably require its source path to resolve from the frozen `.venv/bin/python`).
- Add a negative regression mutating only `external_assets.interpreter` while leaving `command.interpreter` canonical; the pair must FAIL.

## Gate decision

`APPROVE_TO_REGENERATE_P4_V2_D005` is **not granted** yet.

The original verifier FAIL remains non-executing and does not require any GPU rerun. Continue with a root-only static verifier/test correction. Once the interpreter exception is isolated from the general asset/output allowlist and the interpreter asset is explicitly bound to the command interpreter, a fresh clean-worktree regeneration can be re-requested.

This review does not authorize P4 closure, P5, B2-T, D005 argv execution, `torchrun`, GPU, model construction, checkpoint loading for execution, training, evaluation, or inference.
