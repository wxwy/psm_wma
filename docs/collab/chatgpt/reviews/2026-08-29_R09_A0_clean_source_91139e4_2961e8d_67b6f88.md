## HIGH — selected reset does not clear explicit presence state

The backend now correctly represents state as:

```text
(latent[B,D], initialized[B])
```

and replay uses:

```python
present = initialized | mask.bool().any(dim=1)
...
initialized = initialized | mask.bool().any(dim=1)
```

This is the correct direction.

But `reset_mask` still accepts only the latent tensor:

```python
@staticmethod
def reset_mask(state: torch.Tensor, done: torch.Tensor) -> torch.Tensor:
    return torch.where(done[:, None], torch.zeros_like(state), state)
```

The tests/verifier likewise do:

```python
latent, initialized = state
reset = backend.reset_mask(latent, done)
```

and never reset `initialized`.

That violates the frozen contract:

```text
selected reset
-> clear latent for done samples
-> clear presence/initialized for done samples
-> leave both latent and presence unchanged for non-done samples
```

### Failure mode

Suppose sample 2 has already observed valid evidence:

```text
latent[2] != 0
initialized[2] = true
```

Then current reset does:

```text
latent[2] = 0
initialized[2] = true   # stale
```

Next segment is all masked:

```python
present = initialized | mask.any()
        = true | false
        = true
```

So the reset sample becomes present again with a zero latent/token.

This is exactly the episode-leakage semantics A0 is supposed to prevent.

### Required fix

Reset the full backend state, not just latent.

Equivalent APIs are fine, e.g.:

```text
reset_mask(
    state=(latent, initialized),
    done[B]
) -> (latent_reset, initialized_reset)
```

Required assertions:

- selected sample pre-reset latent is nonzero;
- selected sample pre-reset initialized=true;
- after reset selected latent is exact zero;
- after reset selected initialized=false;
- non-selected latent is bitwise/exact unchanged;
- non-selected initialized is exact unchanged;
- after reset + all-masked replay, selected sample remains `present=false`;
- non-selected previously-initialized sample remains `present=true`.

This should be a hard A0 regression.

## MEDIUM-1 — verifier PASS still does not include provenance/clean checks

Even though the current artifact happens to be clean and valid, verifier hard PASS is still:

```python
passed = all(checks.values()) and state_diff <= 1e-6 and token_diff <= 1e-6
```

It does not require:

- root clean;
- submodule clean;
- Gitlink == submodule.

The artifact can therefore still say `status=PASS` on a dirty or mismatched runtime in a future run.

Since the clean values are already computed, simply include them in hard PASS.

Recommended:

```text
provenance_ok =
    root_clean_before
    and submodule_clean_before
    and gitlink == submodule_revision

passed =
    provenance_ok
    and all(contract_checks)
    and segment_tolerances
```

## MEDIUM-2 — permutation isolation still does not cover token/present outputs

Current verifier checks the state tuple:

```text
latent
initialized
```

after batch permutation.

The frozen A0 contract requires batch isolation for observable backend output too.

Check:

- latent/state;
- initialized;
- token;
- returned `present`.

Then unpermute and require exact/declared-tolerance equality.

## MEDIUM-3 — finite check should include backend parameters
