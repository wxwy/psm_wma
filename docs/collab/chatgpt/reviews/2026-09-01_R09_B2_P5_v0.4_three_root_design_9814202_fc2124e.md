# R09-B2 P5 v0.4 three-root static-export design review

- Request: `9814202cee9c291a4c816473fa3105a2523c9e54`
- Design: `fc2124e2a9f5a6095f919a30a8186d20634fb3bb`
- Reviewed Gitlink/submodule: `21d064f2b7c7aeeb67cfee50ac8d6722a944eddb`
- Verdict: **REQUEST_CHANGES**

## Findings

### HIGH — `production_root` must be bound to the D005 frozen absolute worktree identity, not only to revision/Gitlink

The three-root split is the correct architectural fix for the previous single-root contradiction. However, v0.4 currently defines `production_root` primarily by tracked-clean `HEAD=ddb4e0e` plus Gitlink `21d064f`, while the already-closed P4 D005 records freeze absolute path identity as part of the launch contract.

The recurrent D005 records, among other values:

- `command.cwd=/disk/rl/psm_wma_p4_d005_retry/cosmos-framework`
- `environment.set.PYTHONPATH=/disk/rl/psm_wma_p4_d005_retry/cosmos-framework`
- `environment.set.PSM_R09_B2_STREAM_MANIFEST_ROOT=/disk/rl/psm_wma_p4_d005_retry/artifacts/g0/r09/b2/p1_production_manifest_100x16x128`
- the stream-manifest external-asset path under the same absolute root.

Therefore a different clean checkout of `ddb4e0e` at `/some/other/path` is not the same production launch identity. The design text says the child uses the exact D005 cwd/environment, but it does not explicitly require `production_root` itself to equal the root implied by those frozen absolute paths or forbid path remapping.

Required before implementation approval:

1. Derive the expected production worktree root from each verified D005 record (e.g. `Path(command.cwd).parent`) and require both records to agree.
2. Require `production_root.resolve()` to equal that D005-derived root exactly; no relocation/remapping of cwd, `PYTHONPATH`, stream-manifest root, or repo-relative asset root is allowed under the existing D005 v2 contract.
3. Independently verify that every D005 path intended to live under the production worktree resolves under that exact root, while external model/data assets retain their frozen absolute paths.
4. Add a permanent negative: same `ddb4e0e` + same `21d064f` in a different checkout path must FAIL.

If relocation is desired instead, that is a new launch contract/D005 version and must be reviewed separately; P5 must not silently reinterpret the closed P4 D005 pair.

## Positive observations

The v0.4 design correctly separates `production_root`, `evidence_root`, and `exporter_root`; requires independent SHA/provenance validation; removes root-side `tools.g0` imports from child bootstrap; specifies fresh-child exact env/cwd/interpreter checks; and introduces unique staging with PASS-only atomic promotion. Those changes address the major structural issues from the previous review.

## Decision

`APPROVE_TO_IMPLEMENT_P5_V04_STATIC_TOOLS` is **not granted yet**. Only the absolute production-root identity rule above needs to be made explicit in the design before implementation.

No compose/export, `load_experiment_from_toml`, CUDA, torchrun, GPU, training, evaluation, inference, P5 closure, or B2-T is authorized by this review.
