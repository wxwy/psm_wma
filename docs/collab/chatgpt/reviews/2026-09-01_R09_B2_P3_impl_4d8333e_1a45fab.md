## Blocking findings

### HIGH — current collector can PASS while required DCP membership is not inspected
`worker()` always returns `dcp_state={"not_inspected": true, ...}`. The top-level collector nevertheless marks a backend `PASS` whenever the worker exits 0, and can therefore emit overall `PASS` without satisfying the approved P3 contract's DCP/schema membership requirement.

Required fix: either inspect a no-save/no-load state-dict/DCP-compatible schema that proves persistent membership, or mark the backend/P3 `BLOCKED`. `not_inspected` must never be compatible with P3 PASS.

### HIGH — verifier does not verify the inventory contract
`verify_r09_b2_optimizer_inventory.py` currently checks only schema/provenance/no-execution/backend status. It does not hard-gate:
- optimizer object -> unique model parameter reverse mapping,
- duplicate/missing selected trainable parameters,
- exact optimizer param-group membership and metadata,
- actual optimizer-state materialization semantics,
- forbidden TTT five-member state exclusion from parameters/buffers/optimizer/DCP persistent state,
- recurrent-vs-TTT matched diff / allowed differences only,
- complete resolved optimizer selection,
- synthetic fallback prohibition beyond a status string.

Required fix: encode these approved P3 hard gates in machine-verifiable artifact fields and verifier checks. A structural verifier PASS must not imply P3 inventory PASS unless all membership gates pass.

### HIGH — missing-asset path is not actually blocked-safe
`main()` raises `FileNotFoundError` for missing `--wan-vae-path` or `--edge-checkpoint-path` before constructing/writing the artifact. This contradicts the claimed BLOCKED-safe behavior and means a missing asset can produce no auditable BLOCKED artifact.

Required fix: initialize provenance/execution record first and convert missing required assets into explicit `status=BLOCKED` with reason and asset-path evidence; exit without model/config construction. The verifier should accept this only as an honest BLOCKED result, never as P3 closure.

### MEDIUM — current metadata is incomplete relative to approved design
Optimizer group rows omit per-parameter numel/dtype and optimizer state eligibility details, while model rows label `selected_by_recipe` based on actual optimizer membership rather than separately recording resolved selector decision and actual membership. This collapses two layers the approved design explicitly required to distinguish.

Required fix: record selector-match/resolved-selection and actual optimizer membership as separate facts; include stable parameter name, object-identity uniqueness proof, numel/dtype and group metadata.
