# R09-B2 Matched Training Preflight plan review — root 95aa016 / submodule eaa0f97

## Verdict

**APPROVE_TO_PLAN_B2_P0**

This approval is limited to implementing the read-only B2-P0 asset/config/budget audit and its machine-readable verifier. It does **not** authorize matched training, GPU execution, evaluation/inference, backend freeze, or any `cosmos-framework` algorithm/model change.

## Review conclusion

The plan has the right boundary: A1/B1 bounded smoke evidence is treated only as runtime-contract evidence; B2 is explicitly a matched-training engineering comparison rather than a backend-selection result. The same model-only starting checkpoint, same data/cache, same training budget, same precision/optimizer/scheduler/batch/accumulation and same resource class are appropriately frozen, while backend selector plus unavoidable optimizer membership are the only intended backend-specific differences.

The P0 implementation must additionally close the following points before any B2-T run can be approved:

### 1. Exact data-stream identity must be machine-provable

Same seed/config is not sufficient evidence that recurrent and TTT consume the same samples/windows in the same order. P0 must freeze an exact stream identity contract (for example sample/window IDs or an equivalent deterministic stream manifest/hash) and the future B2 verifier must compare it across both runs. Any backend-dependent RNG consumption must not be allowed to perturb the dataloader stream.

### 2. Normal/Zero/Shuffle captures must be non-mutating

The intervention/sensitivity captures must not alter optimizer state, model parameters, recurrent/TTT runtime state, global RNG state, dataloader cursor, or the subsequent canonical training trajectory. P0 must define whether these are performed on cloned inputs/state, a separately restored checkpoint/state, or another machine-checkable non-mutating path. Inline probes that change the compared trajectory are not acceptable.

### 3. Step-budget semantics must be exact

P0 must freeze `optimizer step` as the comparison unit and record the derived samples-per-step/global batch for both backends. The 100-step minimum must mean 100 completed optimizer updates, not dataloader iterations/microsteps. If world-size/microbatch/grad-accum are chosen in P0, they must remain identical across both sides.

### 4. Optimizer membership must be explicit, not inferred

For each side, P0 must record exact trainable parameter names, counts and numel plus optimizer-state membership. The matched diff must distinguish the allowed backend-specific parameter-set difference from every other model/config difference. Prefix-only checks are insufficient.

### 5. Resource provenance must be concrete

P0 should record actual GPU identity/class and available memory, CPU/RAM budget, concurrency state and execution order. Sequential execution is acceptable, but the second run must not be silently given a different resource budget or background-load policy.

## Authorization boundary

After this verdict, Codex may only implement B2-P0 read-only tooling/artifact generation and associated documentation/status updates in the root repository. P0 output must itself return to REVIEW for a new verdict before any B2-T execution.

Still blocked: CPU/GPU training runs, matched training, multi-GPU/long training, eval/inference/closed-loop, SR, backend freeze, RoboTTT/shared-MoT, Global, Agent and RL.
