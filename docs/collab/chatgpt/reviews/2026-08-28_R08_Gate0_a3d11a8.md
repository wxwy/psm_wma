## Summary

Overall direction is correct: root-only diagnostic, no submodule/model/history mutation, A/B share the exact first frame, suffix differs, current training/cache VAE helper is reused, only temporal latent index 0 is compared, and raw z0 sidecars are retained.

However, one HIGH runtime blocker and three MEDIUM evidence/acceptance issues must be fixed before GPU execution.

## HIGH-1 — VAE encode currently retains autograd graphs

Current loop calls:

```python
z0_a = encode_window(a, encoder, device=device)[0]
z0_b = encode_window(b, encoder, device=device)[0]
```

`Wan2pt2VAEInterface.encode()`, `VisionEncoderAdapter.encode()`, and `encode_window()` do not themselves enter no-grad/inference mode. `model.eval()` does not disable autograd.

With 64 anchors × A/B and all z0 tensors retained in `all_sidecar`, this can retain VAE computation graphs and cause progressive GPU memory growth/OOM.

Required fix:

```python
with torch.inference_mode():
    z0_a = encode_window(a, encoder, device=device)[0]
    z0_b = encode_window(b, encoder, device=device)[0]

z0_a = z0_a.detach().cpu().contiguous()
z0_b = z0_b.detach().cpu().contiguous()
```

Prefer wrapping the encode loop in `torch.inference_mode()`.

Acceptance:
- saved sidecar tensors have `requires_grad=False`
- `grad_fn is None`
- no VAE graph is retained across anchors

## MEDIUM-1 — Deterministic runtime is not enforced

The script currently seeds torch/numpy only.

R08 Gate-0 must explicitly enforce/record:
- `torch.backends.cudnn.benchmark = False`
- `torch.backends.cudnn.deterministic = True`
- `torch.use_deterministic_algorithms(True)`
- `CUBLAS_WORKSPACE_CONFIG=:4096:8` (fail-fast or explicit required launch contract)

This project previously observed real latent divergence from `cudnn.benchmark=True`; therefore this is part of causal attribution, not generic hygiene.

Strongly recommended control:
- encode identical A twice: `z0_A1`, `z0_A2`
- record repeat max_abs/L2/SHA
- require repeat exact or within the same frozen numerical tolerance

Then A/B suffix difference can be distinguished from runtime nondeterminism.

## MEDIUM-2 — Anchor selector does not actually guarantee task diversity

The docstring says it prefers episode/task diversity, but implementation groups only by episode and selects the first sorted episodes for each remainder.

The same small set of episodes/tasks may be reused for all four `start_frame % 4` classes.

Required:
- either explicitly stratify by task then episode,
- or emit and gate real coverage fields such as:
  - unique task count per suite
  - unique episode count per suite
  - unique episode count per remainder

Coverage must satisfy the R08 supplement's “different task / episode” requirement for multi-task suites.

## MEDIUM-3 — Canonical PASS threshold must not be user-tunable upward
