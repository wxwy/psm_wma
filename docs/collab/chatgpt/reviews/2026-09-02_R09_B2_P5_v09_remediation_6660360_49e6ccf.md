## Findings

### PASS — previous shared-equality false-PASS is closed

The previous review identified one remaining HIGH: `local_history_backend` was checked only by the cross-envelope diff allowlist. If both envelopes reported the same backend, or both omitted the field, no diff was emitted and the verifier could PASS.

`tools/g0/verify_r09_b2_p5_full_config_diff.py::_bound()` now independently binds each envelope before diffing:

- recurrent envelope must have `resolved_config.model.config.local_history_backend == "recurrent"`;
- TTT envelope must have `resolved_config.model.config.local_history_backend == "ttt_fast_weight"`.

The binding is derived from the verifier-owned/request-bound backend identity, not peer inequality.

### PASS — permanent regressions cover all three forged-equality cases

`tools/g0/test_r09_b2_p5_full_config_diff.py` adds explicit FAIL regressions for:

1. both envelopes set to `recurrent`;
2. both envelopes set to `ttt_fast_weight`;
3. both envelopes omit `local_history_backend`.

These directly cover the exact false-PASS identified in the prior review.

### PASS — v0.9 P3 provenance binding remains intact

The remediation does not weaken the already reviewed v0.9 P3 contract:

- frozen P3 artifact/PASS-verifier identity remains verifier-owned;
- recurrent/TTT backend contracts remain independently recomputed;
- envelope `provenance.p3_contract` remains exact-bound;
- `resolved_config.optimizer.keys_to_select` remains bound to the same-side verifier-owned selector keys.

### PASS — scope remains static and fail-closed

No P4-v4 preflight/refreeze/staging is executed or authorized. The P5 v4 export path remains deliberately blocked by the existing fail-closed adapter/stub, so closing this static tooling review cannot be interpreted as execution authorization.
