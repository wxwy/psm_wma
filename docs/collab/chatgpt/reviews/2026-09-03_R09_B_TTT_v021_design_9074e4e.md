## Closure of prior HIGH-1 — KVB shape contract is now mathematically closed

The prior review required a single exact shape topology so `f_W(K)` and `V` have identical width. v0.2.1 chooses and freezes Option A:

```text
e_b,t                         in R^256
K_b,t = theta_K(e_b,t)        in R^D_ttt
Q_b,t = theta_Q(e_b,t)        in R^D_ttt
V_b,t = theta_V(e_b,t)        in R^32
f_W: D_ttt -> D_ff -> 32
L_inner,b,t = MSE(f_W(K_b,t), V_b,t)
m_b,t = f_W_updated(Q_b,t)    in R^32
local token                   [B,1,32]
```

This removes the previous `D_ttt` versus `D_local=32` mismatch without requiring `D_ttt == 32`.

The fast-state topology is also no longer an abstract single matrix. The canonical pytree is exactly:

```text
W.fast_in.weight   [D_ff, D_ttt]
W.fast_in.bias     [D_ff]
W.fast_out.weight  [32, D_ff]
W.fast_out.bias    [32]
```

with a learned `W0` member-by-member mapping and whole-pytree episode initialization/reset. Exact `D_ttt`, `D_ff`, activation, state dtype, and inner compute precision are deliberately deferred to the static source audit and subsequent implementation-design Gate; that is appropriate for this stage and does not reopen the shape ambiguity.

**Prior HIGH-1: CLOSED.**

## Closure of prior HIGH-2 — per-sample KVB update semantics are now exact

v0.2.1 freezes the canonical inner objective per sample and timestep:

```text
L_inner,b,t = mean_over_local_feature_only(
    (f_(W_b,t-1)(K_b,t) - V_b,t)^2
)

g_b,t[p] = d L_inner,b,t / d W_b,t-1[p]

if valid_b,t:
    W_b,t[p] = W_b,t-1[p] - inner_lr * g_b,t[p]
else:
    W_b,t[p] = W_b,t-1[p]
```

The contract explicitly forbids batch/valid-count/sequence-length/gradient-accumulation/rank scaling of `inner_lr`; invalid samples do not mutate any fast-state member; partial reset and TBPTT detach operate on the whole pytree; and vectorized/vmap implementations must be numerically equivalent to the per-sample reference.

This closes the previous ambiguity where a naive batch-reduced `.mean()` could silently change the effective fast-update step size as packing changed.

**Prior HIGH-2: CLOSED.**

## Required source-audit contracts are sufficiently frozen

The remediation also closes the two prior MEDIUM design gaps and turns them into explicit read-only source-audit deliverables.

### Sequence action forcing / outer-loss normalization

For chronological `[B,T]` training, v0.2.1 now requires:

- independent flow/noise timestep and noise for every valid supervised `(b,t)` item;
- Local history-only/padding/invalid state-carry steps do not contribute native task loss;
- the unchanged Cosmos native item loss is globally averaged over the exact valid supervised timestep set;
- microbatch packing, gradient accumulation, and rank partition must not alter item weights;
- zero-supervision groups do not invent a slow optimizer step.

The source audit must trace the actual current sampler/noise tensor shapes, item-loss reduction point, supervision mask authority, DDP/grad-accum normalization, and exact future adapter seam if the existing trainer cannot express this contract directly.

### Inference autograd boundary

The remediation correctly distinguishes `torch.no_grad()` from `torch.inference_mode()` and freezes the intended ordering:

```text
outside enclosing inference_mode
  -> frozen encoder/QKV produce ordinary detached K/V/Q
  -> local enable_grad scope with only detached fast-state leaves requiring grad
  -> per-sample fast update
  -> detach updated state/readout Local token
  -> frozen Cosmos normal no-grad/inference forward
```

The source audit must trace the real production inference/closed-loop context-manager nesting and identify a legal insertion boundary; it is not allowed to assume a unit-level `enable_grad()` is sufficient inside arbitrary production `inference_mode()`.

## Static source-audit deliverables are adequate

The six required exact tables/sections are sufficient to support a later implementation-design review without allowing the audit itself to make hidden runtime changes:

1. current implementation/gap map with `file:line` evidence;
2. full four-member fast-state pytree inventory, dtype/precision/bytes/W0/reset/TBPTT behavior;
3. proposed slow-parameter inventory and optimizer/checkpoint ownership;
4. sequence action-forcing/loss path audit;
5. production inference context audit;
6. chronological sampler/state-ownership audit across episode IDs, workers, DDP ranks, grad accumulation, retries/replay, epoch boundaries, and partial done/reset.

Particularly important: the source audit must prove whether one episode/transition has a unique fast-state owner. If the current data/trainer pipeline cannot guarantee that, the audit should report the blocker and future seam; it must not repair the pipeline under this Gate.

## RoboTTT alignment check

The retained v0.2/v0.2.1 direction is consistent with the current RoboTTT training recipe at the level relevant to this project: fast weights are updated by gradient descent during training and inference; TTT-KVB uses key/value binding; `Q/K/V` and `W0` are slow learned parameters; sequence action forcing samples flow/noise levels independently per action chunk; and TBPTT detaches fast-weight gradients while carrying the numerical fast state across segment boundaries.

PSM-WMA intentionally differs in placement: TTT remains an independent clean Local Memory modality branch rather than being inserted into the shared policy backbone. That project-specific placement remains explicit and is not misrepresented as identical topology.
