### HIGH-3 — the verifier does not test the frozen tail/update-count contract and does not compare split tokens

The approved source audit explicitly requires CPU coverage for:

```text
N_valid = 1,2,3,5,6,7
update_count = floor(N_valid / 4)
```

and, for N<4, zero W / zero content token with `present=true`.

But `verify_r09_b0_ttt_contract.py:25-31` runs only one 7-step valid sample plus one all-mask sample. It never checks the required N values or update counts.

Also, line 31 computes `split_token`, but lines 32-33 compare only the five state tensors. The token is never compared against the full-replay token. The frozen contract requires exact **state/token/present** equivalence for an unaligned split.

**Required fix:** explicitly serialize and hard-assert:
- each N=1,2,3,5,6,7 case and expected update count;
- N<4 zero-W / zero-token + present=true;
- full vs unaligned split state max diff = 0;
- full vs unaligned split token max diff = 0;
- present exact equality.

### MEDIUM-1 — reported state shapes are supplied constants, not verified actual shapes

`verify_r09_b0_ttt_contract.py:15-16` accepts a caller-provided `shape` and writes it into the artifact, while only bytes are derived from the actual tensor.

At line 28, expected shapes such as `[32,256]` are passed manually. The verifier never asserts `list(value.shape[1:]) == expected_shape`.

Thus the artifact can report the approved shape even if the runtime tensor has a different same-numel layout.

**Required fix:** derive `shape_per_sample` from the actual tensor, compare it to the frozen expected schema, and hard-fail on mismatch.
