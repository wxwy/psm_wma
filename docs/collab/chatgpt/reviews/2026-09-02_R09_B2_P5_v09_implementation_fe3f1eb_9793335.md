## Findings

### HIGH — `local_history_backend` is not validated per side, so shared equality/missing-field forgery can PASS

`tools/g0/verify_r09_b2_p5_full_config_diff.py:88-119` (`_bound`) independently binds the P4-v4 provenance, effective launch and P3 selector, but for `resolved_config` it only requires a mapping plus `optimizer.keys_to_select == verifier-owned selector_keys`. It does **not** require the recurrent envelope to contain `model.config.local_history_backend == "recurrent"`, nor the TTT envelope to contain `... == "ttt_fast_weight"`.

`tools/g0/verify_r09_b2_p5_full_config_diff.py:122-149` (`_allowed`) validates `local_history_backend` only if `diff_paths()` reports that path. Therefore these forged pairs can evade the check:

1. both envelopes set `local_history_backend="recurrent"`;
2. both envelopes set `local_history_backend="ttt_fast_weight"`;
3. both envelopes omit the field/path entirely.

In each case there is no difference at that JSON Pointer, so `_allowed()` is never called for it; `_bound()` can still pass as long as the P3 selectors are correct. This violates the inherited P5 v0.3 contract that the resolved backend is validated **per side before** any backend-diff allowlist is applied, and it weakens the v0.9 statement that `local_history_backend` is an allowed backend-specific difference rather than an optional/unverified field.

Required fix:

- In `_bound()`, require `resolved_config.model.config.local_history_backend` to equal the envelope/request backend (`recurrent` or `ttt_fast_weight`) independently for each side.
- Add permanent CPU negatives for: both recurrent, both TTT, and both missing. Each must FAIL even when all P3 artifact/verifier/backend-contract fields and selectors are otherwise valid.

## Positive observations

- `_p3_contracts()` derives backend contracts through frozen P3 evidence (`_load_frozen_inputs`) and verifier-owned `_p3_contract()` rather than trusting the envelope.
