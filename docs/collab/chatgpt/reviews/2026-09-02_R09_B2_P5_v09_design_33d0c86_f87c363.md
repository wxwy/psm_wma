## Findings

### PASS — P3 truth is made verifier-owned rather than peer-owned

v0.9 closes the remaining v4-envelope P3 binding gap by requiring `provenance.p3_contract` to carry the frozen P3 artifact SHA, frozen P3 PASS evidence/verifier SHA, and the backend-specific selector/optimizer-membership contract. The pair verifier must independently derive both backend contracts from fixed P3 evidence and exact-match each side; envelope self-report or recurrent/TTT mutual agreement is insufficient.

### PASS — resolved selector is tied to the same backend contract

`resolved_config.optimizer.keys_to_select` must exact-equal the same side's verifier-owned `selector_keys`. This prevents a resolved tree from carrying a selector that differs from the P3 optimizer-membership proof while the envelope provenance still appears valid.

### PASS — common evidence and backend-specific differences remain separated

The P3 artifact and PASS-evidence SHA are required to be identical across recurrent/TTT and equal to frozen bytes, while only the verifier-owned backend contract fields may differ. The allowed-difference set remains narrow: backend identity, the three backend-specific P4-v4 evidence SHA values, `PSM_R09_B1_TTT_ENABLED`, the two backend-contract fields, the selector-derived resolved selector, and `local_history_backend`. Unknown JSON Pointer differences remain fail-closed.

### PASS — no conflicting second P3 authority in the current v4 envelope model

The current v4 envelope path at this design anchor has already removed the historical `effective_launch.p1_p3_d005_bindings` representation and retains P3 only as verifier-derived resolved-selector truth. Therefore adding one exact `provenance.p3_contract` does not create two independently mutable P3 contract copies. Implementation must preserve this single-authority model; if another P3 representation is reintroduced, it must be exact-equal to the verifier-owned contract rather than becoming a second source of truth.

## Positive observations

- The change is deliberately narrow and does not reopen P4-v4 handoff, loader, environment, sys.path, staging, roster, or resolved-config canonicalization contracts.
- The design explicitly keeps P3 artifact/PASS evidence as common immutable evidence and backend selector/membership as independently recomputed backend-specific facts.
