# R09-B2 P4 launch D005 design review

- Reviewed commit: `81ce77ea31cd66611580ac369fe96f490967c58e`
- Reviewed Gitlink: `21d064f2b7c7aeeb67cfee50ac8d6722a944eddb`
- Scope: P4 static design only
- Verdict: **REQUEST_CHANGES**

## Findings

### HIGH — the frozen D005 metadata is not yet bound to the production backend/data/budget controls

`docs/build/PSM-WMA_R09_B2_P4_launch_d005_design_v0.1_2026-09-01.md:13-15,47-50,67-80` says P4 closes the exact launcher / sanitized environment / 100-update blocker, but the proposed verifier only compares D005 fields and does not require those fields to be the controls the production launch actually consumes.

At the reviewed Gitlink, production backend selection is environment-driven: `cosmos_framework/configs/base/experiment/action/posttrain_config/action_policy_libero_edge_all.py:70-105` derives `local_history_backend` from `PSM_R09_B1_TTT_ENABLED`, and `action_policy_libero_edge_all.py:200-226` also changes the optimizer `keys_to_select` from that same environment switch. The P4 design instead lists the backend difference as a `command.argv` override while requiring every non-listed field, including environment, to match (`...P4_launch_d005_design...:67-80`). A D005 pair can therefore be internally self-consistent while not representing the production recurrent/TTT switch.

The same trust gap exists for the matched stream and run budget. The production dataloader only consumes the frozen P1 stream when `PSM_R09_B2_STREAM_MANIFEST_ROOT` is present, and then requires `LIBERO_NUM_WORKERS=0`; latent-cache use is controlled by `LIBERO_LATENT_CACHE_ROOT` (`action_policy_libero_edge_all.py:95-145`). The reviewed TOML still has `trainer.max_iter = 5000`, `grad_accum_iter = 16`, `checkpoint.load_path = ${oc.env:BASE_CHECKPOINT_PATH}` and `vae_path = ${oc.env:WAN_VAE_PATH}` (`examples/toml/sft_config/action_policy_libero_edge_all.toml:35-59`). Merely writing `optimizer_updates: 100`, manifest/cache hashes and checkpoint identifiers into D005 does not prove that the future command will consume them.

Required change:

1. Freeze the **actual production control surface**, not parallel metadata. The recurrent and TTT D005s must differ through the reviewed production backend switch (`PSM_R09_B1_TTT_ENABLED=0/1`) or an explicitly reviewed equivalent that also produces the exact corresponding optimizer selector. Do not invent a command-only backend override that bypasses the recipe path.
2. Bind `budget.optimizer_updates=100` to the command/resolved configuration that will actually terminate after 100 optimizer updates. Because the current TOML says 5000, the verifier must require and independently validate an explicit `trainer.max_iter=100` override (or another production-supported mechanism with identical semantics), not just the D005 budget field.
3. Bind each claimed input to the exact production argv/env field that consumes it: at minimum P1 stream manifest root, `LIBERO_NUM_WORKERS=0`, latent-cache root, LIBERO root, base checkpoint, Edge processor checkpoint and required offline controls. A manifest/checkpoint/cache SHA that is not reachable from the frozen launch must fail.
4. Define sanitized-environment semantics. `environment.set/unset` is insufficient if all unspecified parent variables are inherited. Either construct the future process from a verifier-owned allowlist or record/verify the complete allowed inherited environment and fail on unlisted behavior-changing `PSM_*`, `LIBERO_*`, checkpoint/tokenizer/cache/network variables.
5. Add negative regressions where the metadata remains correct but the executable controls are wrong: `optimizer_updates=100` with effective `max_iter=5000`; correct P1 manifest SHA with `PSM_R09_B2_STREAM_MANIFEST_ROOT` absent; TTT metadata with `PSM_R09_B1_TTT_ENABLED=0`; latent-cache metadata with cache env absent. All must fail.

### MEDIUM — the root-relative-only path rule conflicts with an exact launch record

`docs/build/PSM-WMA_R09_B2_P4_launch_d005_design_v0.1_2026-09-01.md:29-30` rejects every absolute path, but the production recipe consumes external runtime assets through environment variables (`BASE_CHECKPOINT_PATH`, `WAN_VAE_PATH`, `LIBERO_ROOT`, `EDGE_POLICY_CHECKPOINT`, and the latent-cache root). An exact D005 cannot both preserve those runtime identities and require every path to be repository-relative.

Required change: distinguish repository-owned artifacts (which should remain root-relative and escape-checked) from external runtime inputs/executable/cwd (which should use canonical absolute realpaths plus identity/hash checks and explicit allowlisted roots). Do not weaken symlink-escape checks for repository-owned outputs.

## Gate decision

Static implementation is **not approved yet**. Revise the P4 design first. This review does not authorize builder/verifier implementation, artifact generation beyond design edits/tests explicitly needed for the revision, P5, B2-T, training, evaluation, inference, or GPU execution.
