## 1. 冻结几何与数学公式

- **Per rank:** B8×T16=128 valid consumers in each full GA; GA2 total N=256 per Optimizer step. Across8 ranks full exposure=2048; per rank **Native Forward+Backward 32→2** under full windows. Terminal partial GA member n_g<128 requires exact count, not padding counted as valid.
- V3 current per index loss: `sum_g sum_t [n_g,t / N] * mean_consumer_loss_g,t`. Packed128 target: `sum_g [n_g / N] * mean_consumer_loss_g` **with true per-consumer (not per-token) reduction**. For full GA2 each packed128 coefficient is 128/256=0.5; do not re-divide by16/2 or multiply by128 twice. To preserve current per-rank objective across potentially uneven ranks, do not silently swap denominator for global 8rank count.
- V3 current`run_member` directly weights full `model.training_step` loss by `n/N`. Historical V2 `GAWindowPlan.objective` separates`consumer_loss*n/N + auxiliary_loss/ga_effective`. For full GA2 n=128 both coefficients=0.5 but for partial/unequal GA may diverge. Need inspect current `aux_loss_{gen,und}` actual presence and verify accounting; if absent verify zero rather than asserting general equation equivalent.
- Packed payload order choose explicit **slot-major (slot0 all T steps, then slot1 ...)** to match V2 `SegmentBatch.gather_consumers()`. Keep per-consumer tuple identity `(slot_id, episode_uid, consumer_step)`, Local Prefix, S0 None and other evidence all aligned. A different flatten order changes RNG assignment if random draws batch-shape-dependent and must be tested.

## 2. 数值和依赖风险（实现 Gate）

1. **TTT高阶链:** `slow_model_params -> evidence_encoder/inner-update(create_graph=True) -> W_fast,t -> LocalPrefix[t] -> packed outer loss -> slow grads`. Must never detach LocalPrefix, skip `create_graph=True` or use no_grad for scan. Outer one backward for all128 prefixes per GA; if graphs are self-contained and state at boundary detached, `retain_graph` may beFalse, but CPU/GPU probes must establish. Source evidence`local_evidence.py::step_many` uses `torch.autograd.grad(...,create_graph=True)`.
2. **Per-sample loss/reduction:** packed attention/sequence plan boundary must isolate sample tokens as intended; `sample_level_loss_averaging`, per-token masks/action/vision weighting, padding/terminal valid mask and optional load balancing aux must be separately compared. A 128 sample pack cannot create cross-sample leakage or wrongly count padded/invalid data.
3. **RNG:** sigma/epsilon, `torch.randn`, CFG dropout, stochastic routing and token packing consume random streams differently when shape goes Batch8×16 calls→Batch128×1. Same seed does NOT guarantee same per-sample draws. First run deterministic controlled inputs (sigma=0.5, epsilon fixed, dropout disabled, same weight and sample identity), then test training-mode statistical/paired RNG contract or per-consumer keying before claiming exact resume numerical equality.
4. **FSDP gradient:** active trainable inventory by stable FQN (historically314 tensors total, not hardcoded replacement); compare full ranklocal sharded and when practical unsharded grad after two GA members, `generation/action/local` norms, relative L2 + cos + missing/nonfinite counts; rankworld all8 must execute same collective rhythm, no unwanted new sync/hang. GradScaler, optimizer and scheduler update **once** per complete GA2 step, including overflow skip; no stale grads.
5. **Local state authority:** same initial W_fast, identical scan/prefix/after-state, B8 per-slot/chronology, terminal shortened row, S0 absent prefix, rebind, failure abort; Candidate Fast States, Frontier and schedule publish only after successful Optimizer Step, not when Packed128 backward starts/ends. DCP restore/resume identity and source/Digest constraints unchanged.
6. **Callback/metrics:** before/after-forward/backward hooks now fire2 instead of32 times; audit any side-effectful callback. `native_forward_calls` + `native_backward_calls` 2; `valid_consumers` still256 per rank; JSONL action/vision/aux loss coverage and weighted totals must adapt from`index` to packed-member sample counts rather than using `index=0` weight8/256. Incorrect observer weighting is a *measurement bug* even if optimizer loss correct.
7. **Precision and evidence:** CPU FP32 synthetic exact sample/identity/normalized loss/gradient, followed by real H100 no-update fixed-input pack-vs-index with per-group FQN gradient and selected optimizer one-step parity. Current V2 historical packed vs scalar fixed inputs had Loss rel3.0e-5 and gradient L2 2.39% (old threshold5%)—evidence packed possible, **not automatically accepted tolerance for V3**. Freeze V3 thresholds *before* looking at PASS numbers; report isolated nondeterministic effects and gradient per-group, not only total norm.
8. **Resources:** Owner authorizes directly tryingBatch128 on availableH100, not gradual size tuning. GPU memory allocation must still be fail-closed on OOM: no silent batch shrink or altered GA/consumer count; no interruption of existing production train.
