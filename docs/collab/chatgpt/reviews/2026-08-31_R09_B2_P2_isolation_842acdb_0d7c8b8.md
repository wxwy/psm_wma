# R09-B2 P2 CPU isolation re-review

- Root evidence commit: `842acdb1b7d7e0780690dae7e2f47521b368c4d2`
- Submodule/Gitlink: `0d7c8b8a66e48e0f11abc83a533cc2787320633f`
- Verdict: **REQUEST_CHANGES**

## Findings

### HIGH — the callback still does not enforce the isolation snapshot contract

`cosmos_framework/callbacks/r09_b2_capture.py` adds `IsolationSnapshot`, `take_isolation_snapshot()` and `require_unchanged()`, but `R09B2NonMutatingCaptureCallback.on_training_step_end()` remains the earlier clone-only implementation. It does not take a before snapshot, execute capture, take an after snapshot, and fail closed on any protected-state mutation. The new root collector proves only that the standalone helper can detect deliberately mutated synthetic dictionaries; it does not prove the actual callback is guarded by that helper.

Required closure: wire the callback (or a wrapper that is the only callable P2 entrypoint) so CPU tests prove the real capture path performs before/after isolation verification and rejects mutations on every exception/success path. The callback must still not access or forward the canonical model/runtime beyond explicitly supplied snapshot material.

### HIGH — TTT runtime-state evidence does not use the frozen B1 five-member schema

Both the submodule test and `tools/g0/collect_r09_b2_nonmutating_capture.py` synthesize TTT state keys `fast_weight/lr/segment/reset/detach`. The frozen B1 runtime schema is exactly:

- `W`
- `pending_evidence`
- `last_evidence`
- `initialized`
- `segment_progress`

P2 is required to hash the complete backend runtime state, so the contract must use the exact frozen names/schema (and reject missing/extra members), not a generic five-key placeholder.

### MEDIUM — RNG snapshot is CPU-only and cursor metadata is incomplete

`take_isolation_snapshot()` hashes only `torch.get_rng_state()`; the approved design explicitly covers CPU/CUDA RNG states. The implementation can remain CPU-tested, but the snapshot schema/helper should represent CUDA RNG state when CUDA exists so a later runtime use cannot silently omit it.

Also, the callback currently records only `b2_stream_ordinal` and `b2_stream_epoch`; the approved P2 contract includes immutable consumed-batch ordinal/epoch/microbatch metadata. The P1 manifest path should expose and P2 should hash the required microbatch identity rather than weakening the contract.

## What is accepted

- Synthetic mutation evidence now covers parameters, buffers, optimizer, scheduler, batch metadata, recurrent state and TTT-state categories.
- `require_unchanged()` is fail-closed when two snapshots differ.
- Clone-only Normal/Zero/Shuffle and RNG `finally` restoration remain directionally correct.
- No GPU/training/model-runtime execution is authorized by this review.

## Gate

P2 remains **OPEN / REQUEST_CHANGES**. Do not start P3-P5, B2-T, GPU, training, eval/inference or closed-loop work from this commit.
