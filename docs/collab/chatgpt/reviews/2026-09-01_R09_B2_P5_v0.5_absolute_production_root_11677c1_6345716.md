# R09-B2 P5 v0.5 D005 absolute production-root design review

## Findings

No blocking findings in the v0.5 absolute-production-root scope.

The design now treats the P4 D005 worktree path as part of the frozen launch identity rather than allowing arbitrary relocation of a matching Git revision. The parent must derive the production root independently from both verified D005 `command.cwd` values, require the derived roots to match, and require the supplied canonical `production_root.resolve()` to equal that frozen path. For the currently closed P4 v2 pair, the only allowed production root is `/disk/rl/psm_wma_p4_d005_retry`.

The contract also correctly extends that absolute worktree binding to D005 values that are semantically rooted inside the production checkout: `command.cwd`, `environment.set.PYTHONPATH`, `PSM_R09_B2_STREAM_MANIFEST_ROOT`, and the stream-manifest external asset path. External model/data/VAE/checkpoint assets remain bound to their own frozen absolute paths and do not gain a broad production-root containment exception.

The design explicitly rejects a clean checkout of the same `ddb4e0e`/`21d064f` revision at another absolute path, rejects symlink aliases and path remapping, and requires a permanent CPU regression for that case. This preserves the already-closed P4 v2 launch contract rather than silently introducing relocation semantics during P5.

The inherited v0.4 three-root model remains appropriate: production source, committed evidence, and exporter implementation are separate read-only trust roots; child bootstrap remains production-only; staging is attempt-scoped and only promoted after full verification.

## Gate decision

`APPROVE_TO_IMPLEMENT_P5_V05_STATIC_TOOLS` is granted narrowly.

Authorized only:
- root-side static refactor of the P5 exporter/verifier/CPU fixtures to implement the v0.4 + v0.5 contracts;
- read-only/static checks needed by those fixtures.

Not authorized:
- static config export execution;
- `load_experiment_from_toml` execution against the real production recipe;
- CUDA/GPU, `torchrun`, model/trainer/dataloader/optimizer/checkpoint construction;
- training, evaluation, inference;
- P5 closure or B2-T.
