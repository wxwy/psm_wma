## Blocking changes before APPROVE_TO_ADVANCE_B0_SOURCE_AUDIT

### 1. MEDIUM — segment_steps / inner_steps semantics are coupled incorrectly

File:
`docs/build/PSM-WMA_R09_B_TTT_preflight_runbook_v0.2_2026-08-30.md:21`

Current text freezes:

```text
segment_steps >= inner_steps
and
segment_steps divides sample forward-step count
```

This is not a valid generic TTT invariant.

`segment_steps` is a temporal/evidence-span quantity; `inner_steps` is the number of inner optimization/update iterations. There is no inherent requirement that the temporal span be greater than or equal to the number of inner updates. A candidate may legitimately perform multiple inner updates from one segment.

Likewise, exact divisibility is not a universal requirement; a valid implementation may support a final shorter tail segment.

More importantly, `forward step` is ambiguous here. For the first B0 contract, state carry must remain inside one sample/window and should be defined over explicit contiguous slices of the causal evidence axis `H`. It must not silently mean carry across outer trainer/policy forwards.

Required fix:

- define `segment_steps` as the number of valid causal **evidence timesteps** consumed per explicit replay segment within one sample/window for B0;
- preserve `state_start=zeros` per sample/window;
- remove the global `segment_steps >= inner_steps` rule;
- remove mandatory divisibility, or explicitly permit a shorter final tail segment;
- any future state carry across policy/control forwards must be a separate later gate.
