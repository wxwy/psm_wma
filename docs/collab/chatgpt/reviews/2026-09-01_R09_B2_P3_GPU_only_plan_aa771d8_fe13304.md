## Decision

The plan is sufficiently scoped to move from the closed CPU/meta `BLOCKED` attempt to implementation of a separate GPU-only, read-only inventory Gate. It correctly keeps implementation and GPU execution as separate approvals and preserves the prohibition on B2-T, P4/P5 runtime, training, eval/inference/closed-loop, multi-GPU, long training and backend freeze.

The three previously identified future-PASS weaknesses are now explicitly frozen as implementation policy:

1. the recurrent-only difference prefix must be verifier-owned and not artifact-controlled;
2. `selector_optimizer_exclusions` must be empty and resolved selector membership must equal actual optimizer membership;
3. optimizer state / persistent state membership must be obtained from real objects and checked against the five frozen TTT runtime members.

## Implementation hard requirements

These are requirements for the implementation review; they do **not** authorize GPU execution now.

1. **Verifier-owned policy only.** Hard-code `ALLOWED_RECURRENT_ONLY_PREFIXES=("local_history_runtime.recurrent_backend.",)` in verifier source. Any artifact-side allowed-prefix field is evidence only and must equal the verifier constant exactly. `selector_optimizer_exclusions` must be absent/empty; no artifact-side override mechanism may affect PASS.
2. **Actual object membership.** Persist stable parameter names/numel/dtype plus object-identity reverse-map results for optimizer groups. PASS requires exact selector==optimizer membership for each backend, no duplicates/unmapped objects, and no TTT-only difference.
3. **Optimizer-state semantics.** Read the real optimizer `state` / `state_dict()` without `step()`. If state is initially empty, record `not_materialized=true` and an exact eligibility set derived from param groups; do not fabricate Adam tensors. If any state is materialized by construction, map every entry back to a stable model parameter and record state-key/tensor metadata.
4. **DCP-compatible schema must be bound to the real serialization path.** `model.state_dict()` / `optimizer.state_dict()` alone may not be labeled as proof of trainer-DCP membership unless the implementation also records the exact checkpoint/DCP serialization source symbol(s)/file SHA showing that those are the objects serialized by the production checkpoint path. If that binding cannot be established without save/load or mutation, return `BLOCKED`; do not weaken the claim to PASS.
5. **TTT fast-state exclusion.** `W`, `pending_evidence`, `last_evidence`, `initialized`, `segment_progress` must be absent from named parameters, named buffers, optimizer membership/state and the proven persistent checkpoint schema.
6. **Cross-backend matched diff.** Recompute recurrent-vs-TTT selector/optimizer/persistent-state differences inside the verifier. Only recurrent names under the verifier-owned prefix may differ; any TTT-only or other recurrent-only name is FAIL.
7. **Execution guardrails.** Implementation must prepare D005-lite/provenance and fail-closed guards for single-process/single-GPU, no distributed/FSDP, no dataloader/VAE/tokenizer/data/base-checkpoint load, no forward/backward/optimizer/scheduler step, no checkpoint save/load, and <=24 GiB peak allocated/reserved threshold as specified by the plan.
8. **No synthetic fallback.** If real full-recipe model/optimizer construction or required persistent-schema inspection cannot be completed inside the frozen execution surface, canonical result is `BLOCKED`, never a synthetic PASS.
