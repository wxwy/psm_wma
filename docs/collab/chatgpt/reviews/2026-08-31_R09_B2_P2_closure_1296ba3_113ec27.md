# R09-B2 P2 closure review — request 1296ba3 / implementation 5fdb00b / submodule 113ec27

## Verdict

**REQUEST_CHANGES**

P2 is not ready to close. The helper is appropriately narrow and the RNG context manager is directionally correct, but the implementation does not yet implement the fail-closed isolation contract that was approved in the P2 plan.

## Blockers

### HIGH 1 — before/after isolation hashes are not actually implemented

The approved contract required capture-time before/after comparison of model parameters **and buffers**, optimizer state, scheduler state, CPU/CUDA RNG, immutable batch ordinal metadata, and complete Local runtime state, with any change causing FAIL.

`R09B2NonMutatingCaptureCallback.on_training_step_end()` currently deletes `model/output_batch/loss`, clones only `data_batch['local_memory']`, and records ordinal/epoch. It does not snapshot or compare any canonical model/buffer, optimizer, scheduler, Local runtime state, or batch metadata before/after.

The root artifact then records booleans such as `snapshot_mutation_detected=true` and `canonical_model_untouched=true`, while the verifier only checks that those booleans are present and true. That is self-attestation, not machine evidence of the approved isolation contract.

Required fix: introduce an explicit isolation snapshot structure/helper and verifier-consumable before/after hashes. The callback/test harness must fail closed when any protected component differs. For CPU-only closure, fake/minimal model/optimizer/scheduler/runtime objects are sufficient; no real model loading is required.

### HIGH 2 — full Local runtime-state contract is absent

The approved design explicitly required complete backend runtime-state hashing: recurrent complete recurrent state representation and TTT frozen five-member state. The current callback consumes only `local_memory` payload tensors and has no runtime-state clone/snapshot API or corresponding tests.

Required fix: define a backend-neutral snapshot input contract that can represent both recurrent state and the TTT five-member schema, and add CPU tests proving mutation detection for each required state member. This can remain pure CPU metadata/tensors and must not instantiate the real model.

### HIGH 3 — mutation/exception negative tests are incomplete relative to the approved plan

Current tests cover RNG restoration after exception, invalid mode/payload, generic tensor/metadata hash mutation, and no access to the canonical model. They do **not** prove fail-closed detection for parameter, buffer, optimizer, scheduler, Local runtime, and immutable batch ordinal mutations as individually required by the approved plan.

Required fix: add explicit negative tests for all protected classes and make the root artifact derive its PASS from those concrete tests/checks rather than manually asserted booleans.

## Non-blocking observations

- `isolated_rng()` correctly restores CPU RNG in `finally`, and has CUDA restoration logic when CUDA is available.
- The callback does not invoke the canonical model, which satisfies the second-forward prohibition for this CPU-only helper stage.
- `normal/zero/shuffle` operate on detached clones and do not mutate the source payload in the current tests.

## Scope

No GPU/model/VAE/optimizer loading, training, B2-T, P3-P5, eval or inference is authorized. Only the P2 CPU isolation-contract implementation/tests/verifier/artifact may be revised and resubmitted.
