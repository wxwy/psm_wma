## Review

The previous launch-binding blockers are closed at the design level.

1. `command.cwd` is now frozen to the canonical `<repo>/cosmos-framework` realpath. This matches the production Edge configuration, which still resolves the Nemotron JSON from a framework-relative filesystem path. Root-repo cwd, symlink aliases, missing cwd and alternate cwd values are explicitly negative cases.
2. The future launch no longer trusts `PATH` to resolve `torchrun`. `command.argv[0]` is bound to the recorded canonical `.venv/bin/python` realpath and SHA256, followed by `-m torch.distributed.run --standalone --nnodes=1 --nproc-per-node=1 -m cosmos_framework.scripts.train`.
3. `--sft-toml` is frozen to the single framework-relative `examples/toml/sft_config/action_policy_libero_edge_all.toml` under that exact cwd. This removes the previous cwd-dependent ambiguity.
4. The prior output/resume and single-process controls remain intact: backend-specific `IMAGINAIRE_OUTPUT_ROOT`, production-derived job/checkpoint paths, fresh/no-`latest_checkpoint.txt` protection, `CUDA_VISIBLE_DEVICES=0`, one-process launcher, explicit `trainer.max_iter=100`, and `trainer.save_zero_checkpoint=true`.
5. P4 remains a static, non-executable contract. No approval token is embedded and no `torchrun`, model/data/checkpoint/VAE I/O, GPU, training, evaluation or inference is authorized by this review.

## Gate decision

`APPROVE_TO_IMPLEMENT_P4_STATIC_D005`

Scope is limited to the static builder/verifier/tests and `FROZEN_NOT_EXECUTED` artifacts described by the reviewed design. The implementation must preserve the documented fail-closed negative cases and must not import/launch Cosmos/PyTorch runtime code as part of P4 generation/verification.

This review does **not** approve P4 closure, P5, B2-T, any future launch, GPU execution, training, evaluation, inference, closed-loop, multi-GPU, or backend freeze. After implementation and CPU/static tests are committed, submit a new review request for implementation closure.
