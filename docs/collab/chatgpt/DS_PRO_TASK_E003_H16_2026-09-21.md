## Unified switch

The only user-facing history selector is:

```bash
PSM_HISTORY_MODE=none|window|gru|ttt
```

Frozen semantics:

| mode | history | representation into MoT | persistent state |
|---|---|---|---|
| none | none | current observation only | no |
| window | last H=16 completed steps | native full-spatial clean vision latents + clean executed actions | bounded only |
| gru | last H=16 completed steps | visual96+action10 -> zero-state GRU replay -> 1x32 Local | bounded only |
| ttt | full episode | fast-weight update -> 1x32 Local | episode-level |

Important:
- WINDOW has no Local token, no GRU and no learned history compressor.
- WINDOW history observations are the first causal latent of each exact-window cache entry, kept at full spatial latent resolution.
- WINDOW and history actions are aligned on the same FPS-aware source-frame mRoPE clock.
- fully-clean WINDOW history vision items do not dilute the WAM target vision loss.
- GRU starts recurrent replay from zero every policy query.
- TTT fast state persists across detached 16-step segments for the full episode.
- `ttt_tbptt_steps=16` is graph truncation, not TTT memory horizon.
- episode reset restores TTT fast state to latest slow W0 in training / checkpoint W0 in inference.

Do not change H, optimizer scope, loss weighting, action alignment, Local dim or model structure during the formal experiment.
